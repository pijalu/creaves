# Startup reference-data internationalization plan

## Scope

Translate every non-empty French user-facing string in `grifts/creaves-startup.sql.gz` into `fr`, `en-US`, `de`, and `nl`, then make `buffalo task db:seed` install those entries idempotently.

Source language remains French. Table and field names provide translation context.

## Goals and definitions of done

### Goal 1 — Canonical inventory and extractor

- Replace scattered field lists with one authoritative startup translation inventory.
- Parse seeded rows by column name, including species primary key `ID`.
- Skip NULL and empty values; preserve Unicode, apostrophes, CR/LF, and dosage text.
- Produce deterministic worksheet/manifest containing table, record ID, field, and French value.

**Done when:** extractor test proves all 4,011 audited values are discovered and every configured field exists in dump/schema.

### Goal 2 — Translation production

- Translate each French value into English, German, and Dutch using table/field context.
- Preserve scientific names and proper nouns where translation is inappropriate.
- Preserve multiline list structure for descriptions.
- Keep dosage units semantically equivalent.
- Review terminology consistently across repeated values.

**Done when:** worksheet has non-empty reviewed target values for all source rows, with intentional exceptions explicitly recorded and approved.

### Goal 3 — Seed artifacts and loader

- Generate embedded `translations_en-US.sql`, `translations_de.sql`, and `translations_nl.sql`.
- Generate French rows from seeded base tables, rather than duplicating dump literals manually.
- Accept hyphenated `en-US` locale filename.
- Use unique-key-aware insert/update policy that adds missing rows but never overwrites existing administrator edits.
- Keep `db:seed:startup` and `db:seed` behavior aligned.

**Done when:** fresh database receives all locales; partially seeded database receives missing rows; rerun produces no duplicates or value loss.

### Goal 4 — Verification and operational documentation

- Add unit tests for extraction, locale parsing, SQL escaping, coverage, and idempotency.
- Run MySQL-backed seed checks required by project guide.
- Document generation commands, translation review workflow, and rollback procedure.

**Done when:** `go test ./grifts ./models ./utils`, relevant integration tests, and two consecutive real `db:seed` runs pass.

## Execution order

1. Implement inventory and parser/manifest tests.
2. Generate French worksheet and target-language translation worksheet.
3. Translate and review reference data in table-context batches.
4. Implement SQL generation and locale-aware loader.
5. Generate and embed SQL artifacts.
6. Run unit tests, migration, fresh seed, repeat seed, and SQL coverage queries.
7. Review diff for accidental source-data changes and document rollback.

## Translation rules

- `animaltypes`, `animalages`, `species`: wildlife/taxonomy context.
- `caretypes`, `outtaketypes`: animal-care and release workflow context.
- `drugs`, `dosages`: veterinary context.
- Scientific taxon names remain scientific names unless an established localized common name is clearly intended.
- Empty source values do not create translation rows.
- Translation values never alter canonical French columns.

## Rollback

- Revert generated translation SQL and loader changes as one change set.
- Existing database rows remain safe because loader never overwrites non-empty values.
- If a bad translation is deployed, update the affected translation row through admin UI or a reviewed corrective seed migration; do not modify source reference rows.

## Validation queries

```sql
SELECT locale, COUNT(*) FROM translations GROUP BY locale;
SELECT table_name, field, locale, COUNT(*)
FROM translations
GROUP BY table_name, field, locale
ORDER BY table_name, field, locale;
```

Expected coverage: every non-empty manifest key exists for each delivered locale, with one unique row per `(table_name, record_id, field, locale)`.
